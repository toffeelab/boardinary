# 001 — 프로젝트 핵심 신념

> 상태: 확정 | 날짜: 2026-03-30

## 에이전트 우선 개발

코드, 문서, 테스트 모두 에이전트가 읽고 실행할 수 있어야 한다. 에이전트의 관점에서 실행 중에 컨텍스트 내에서 접근할 수 없는 것은 사실상 존재하지 않는 것이다.

## 리포지터리 = 기록 시스템 (System of Record)

Google Docs, Slack 스레드, 머릿속 지식은 에이전트가 접근할 수 없다. 모든 결정, 원칙, 컨텍스트를 리포지터리 내 버전 관리되는 아티팩트(코드, 마크다운, 스키마, 실행 계획)에 인코딩한다.

## 기계적 강제 > 문서화

문서화만으로는 에이전트가 규칙을 위반할 수 있다. 린터, 구조적 테스트로 강제할 수 있는 규칙은 코드로 인코딩한다. 린트 에러 메시지에 수정 방법을 포함하여 에이전트 컨텍스트에 지침을 주입한다.

## 점진적 공개

에이전트가 처음부터 모든 정보에 압도되지 않도록 한다:
1. **CLAUDE.md** — 프로젝트 맵, 어디를 봐야 하는지 안내
2. **docs/** — 도메인별 상세 가이드
3. **코드** — 실제 구현과 테스트

## Worktree 격리

여러 세션이 병렬로 작업하므로 메인 디렉토리는 항상 develop의 클린 상태를 유지한다. 코드 구현은 반드시 worktree에서 수행한다.

## 진화하는 하네스

가장 단순한 해결책부터 시작하고, 필요할 때만 복잡성을 증가시킨다. 모델이 개선되면서 불필요한 스캐폴딩은 제거하고 새로운 능력을 활용한다.
