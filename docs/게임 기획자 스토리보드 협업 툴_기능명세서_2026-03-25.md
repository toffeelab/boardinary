## 1. 프로젝트 개요
---
### 카테고리
> 생산성 / 업무

### 한 줄 정의
게임 기획자 스토리보드 협업 툴

### 배경
기존 게임 개발 환경에서는 스토리보드 작성을 위해 파워포인트, 키노트와 같은 일반적인 문서 도구나 Figma 같은 디자인 툴을 활용하는 경우가 많습니다. 이러한 도구들은 게임 스토리보드에 특화되어 있지 않아 협업 시 버전 관리의 어려움, 실시간 피드백의 비효율성, 템플릿 부재로 인한 작업 시간 소모, 문서 일관성 부족 등의 문제를 야기합니다. 이는 결국 프로젝트 지연과 커뮤니케이션 오류로 이어질 수 있습니다.

### 사용자 문제
1. **비효율적인 협업**: 여러 기획자가 동시에 작업하거나 다른 팀원과 공유할 때 버전 충돌, 수동 병합 등으로 인해 협업 효율성이 저하됩니다. 2. **어려운 버전 관리**: 문서의 변경 이력을 추적하고 특정 시점으로 되돌리기가 어려워 중요한 내용이 손실되거나 혼란이 발생합니다. 3. **긴 스토리보드 작성 시간**: 게임 특화된 템플릿이나 컴포넌트 부재로 인해 초기 세팅 및 반복적인 작업에 많은 시간이 소요됩니다. 4. **문서 일관성 부족**: 통일된 양식이나 가이드라인 없이 개별적으로 작업하여 문서 간 일관성이 떨어지고, 이는 이해도를 저하시키고 불필요한 재작업을 유발합니다. 5. **피드백 및 주석 관리의 어려움**: 스토리보드에 대한 피드백을 주고받는 과정이 분산되어 관리하기 어렵고, 실시간 반영이 어렵습니다.

&nbsp;

### 해결 방식
게임 기획에 최적화된 드래그 앤 드롭 방식의 스토리보드 편집 기능을 제공하여 직관적인 UI/UX를 통해 쉽고 빠르게 스토리보드를 작성할 수 있도록 돕습니다. 실시간 협업 기능을 통해 여러 명의 기획자가 동시에 작업하고, 강력한 버전 관리 시스템으로 문서 변경 이력을 체계적으로 관리하며, 주석 및 피드백 기능을 통해 원활한 커뮤니케이션을 지원합니다. 또한, 게임 유형별 특화된 템플릿과 다양한 내보내기 형식을 제공하여 문서의 일관성을 확보하고 외부 도구와의 연동성을 높입니다.

### 차별점
기존의 일반적인 문서/디자인 툴로는 해결할 수 없었던 게임 기획 특유의 스토리보드 작성 및 협업 문제에 집중하여, 게임 기획자만을 위한 최적화된 워크플로우와 기능을 제공합니다. 특히 실시간 동시 편집, 시각적 버전 관리, 게임 특화 템플릿, 주석 및 피드백 통합 관리 기능을 통해 파워포인트/디자인 툴의 한계를 뛰어넘고, 기존 업계의 스토리보드 툴들보다 압도적인 사용 편의성과 효율성을 제공하여 혁신적인 경험을 선사합니다. Jira, Slack과의 통합을 통해 기존 개발 파이프라인에 자연스럽게 녹아들 수 있도록 지원합니다.

### 타겟 사용자
게임 개발 스튜디오 소속의 게임 기획자 또는 인디 게임 개발자. 특히 여러 명의 기획자가 함께 작업하거나, 디자이너, 개발자 등 다른 직군과의 협업이 잦은 환경에 있는 사용자를 대상으로 합니다. 복잡한 게임의 내러티브나 시스템 흐름을 시각적으로 명확하게 정리하고 공유해야 하는 필요성을 느끼는 사용자입니다.

### 사용 시나리오
1. **스토리보드 생성**: 게임 기획자 A는 새로운 게임 프로젝트를 시작하며, 툴에서 제공하는 RPG 장르 템플릿을 선택하여 빈 스토리보드를 생성합니다. 2. **드래그 앤 드롭 편집**: A는 좌측 팔레트에서 캐릭터, 배경, UI 요소 등을 드래그 앤 드롭하여 메인 퀘스트 흐름을 시각적으로 구성합니다. 각 요소에 설명, 대사, 조건 등을 입력합니다. 3. **실시간 협업**: 팀원인 기획자 B와 C를 프로젝트에 초대합니다. B는 전투 시스템 스토리보드를, C는 아이템 획득 흐름을 동시에 작업합니다. 서로의 작업 내용을 실시간으로 확인하며 의견을 주고받습니다. 4. **피드백 및 주석**: A는 B가 만든 전투 스토리보드에 특정 스킬 발동 조건에 대한 의문점을 주석으로 남깁니다. B는 즉시 주석을 확인하고 답변하며, 필요시 스토리보드를 수정합니다. 5. **버전 관리**: 프로젝트 진행 중 중요한 변경사항이 발생했을 때, A는 이전 버전으로 돌아가 변경 내역을 확인하고 필요에 따라 복원합니다. 6. **외부 연동 및 내보내기**: 완성된 스토리보드는 Jira에 연동하여 개발 태스크로 전환하고, PDF 또는 이미지 파일로 내보내어 디자이너 및 개발팀과 공유합니다.

## 1. 스토리보드 실시간 협업 편집

**수용 기준:**
```
1. ○ 두 명 이상의 사용자가 동일한 스토리보드를 동시에 열고 편집할 때 각 사용자의 변경 사항이 지연 없이 즉시 다른 사용자에게 표시되어야 합니다.

3. ○ 현재 스토리보드를 편집 중인 다른 사용자들의 커서 위치 또는 편집 영역을 시각적으로 확인할 수 있어야 합니다.
```

## 7. AI 기반 스토리보드 초안 생성 및 개선
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

기획 텍스트를 입력하면 요소/연결선/기본 속성을 포함한 스토리보드 초안을 생성하고, 기존 스토리보드를 분석해 개선안을 제안하며, 요소의 대사/설명 문장 초안을 생성·정리할 수 있어야 합니다. 모든 AI 제안은 항상 미리보기로 제공되고 사용자 승인 후에만 적용되며, 적용 시 자동 버전을 생성해 되돌리기를 지원해야 합니다.

**수용 기준:**
```
1. ○ 사용자는 텍스트 입력(시놉시스/퀘스트 설명/대사 리스트 등)으로 스토리보드 초안(요소/연결선/기본 필드 포함)을 생성할 수 있어야 합니다.
2. ○ 사용자는 기존 스토리보드에 대해 AI 개선안(누락/불일치/흐름 오류 등)을 받을 수 있어야 하며, 개선안은 항목별로 선택 적용할 수 있어야 합니다.
3. ○ 사용자는 선택한 요소의 대사/설명/조건 문장 초안을 생성하거나, 기존 문장을 정리(간결화/용어 통일)할 수 있어야 합니다.
4. ○ AI 결과는 항상 미리보기로 제공되어야 하며, 사용자 승인 없이 보드에 반영되면 안 됩니다.
5. ○ AI 결과를 적용하는 순간마다 자동 버전을 생성해야 하며, 사용자는 해당 버전으로 되돌릴 수 있어야 합니다.
6. ○ AI가 생성/수정한 이름/문장에 대해 조직 용어집(이름 규칙/스타일 가이드) 위반을 감지하고 경고 또는 자동 교정(가능 범위)을 제공해야 합니다.
```


### 7.1 텍스트 입력→스토리보드 초안 생성
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전 | **역할**: 게임 기획자, 프로젝트 관리자 | **기기**: 웹 브라우저, Windows 데스크톱 애플리케이션, macOS 데스크톱 애플리케이션

시놉시스/퀘스트 흐름/대사 리스트 등의 텍스트를 입력받아 요소·연결선·기본 속성 초안을 생성하고 미리보기로 제공한다.
