# ESLint Custom Rule Patterns

프로젝트에서 자주 사용하는 ESLint 커스텀 규칙 패턴 3가지.
각 패턴에 대해 ESLint 9 flat config와 legacy config 예시를 모두 제공한다.

---

## 1. Import 경계 강제

### 목적

특정 모듈(예: DB 모듈)을 지정된 레이어(예: data-access)에서만 import할 수 있도록 제한한다.

### 왜 필요한가

DB 직접 접근을 모든 곳에서 허용하면 쿼리 로직이 흩어져 유지보수가 어려워진다.
data-access 레이어를 통해서만 DB에 접근하도록 강제하면 변경 영향 범위를 줄일 수 있다.

### ESLint 9 Flat Config

```js
// eslint.config.js
import { defineConfig } from "eslint/config";
import restrictedImports from "eslint-plugin-no-restricted-imports"; // 또는 내장 규칙 사용

export default defineConfig([
  {
    files: ["src/**/*.ts", "src/**/*.tsx"],
    ignores: ["src/data-access/**"],
    rules: {
      "no-restricted-imports": [
        "error",
        {
          patterns: [
            {
              group: ["@/db/*", "@/db"],
              message:
                "DB 모듈은 data-access 레이어에서만 import하세요. @/data-access/* 를 사용하세요.",
            },
          ],
        },
      ],
    },
  },
]);
```

### Legacy Config (.eslintrc.json)

```json
{
  "overrides": [
    {
      "files": ["src/**/*.ts", "src/**/*.tsx"],
      "excludedFiles": ["src/data-access/**"],
      "rules": {
        "no-restricted-imports": [
          "error",
          {
            "patterns": [
              {
                "group": ["@/db/*", "@/db"],
                "message": "DB 모듈은 data-access 레이어에서만 import하세요."
              }
            ]
          }
        ]
      }
    }
  ]
}
```

### 테스트 방법

```bash
# data-access 외부에서 DB import 시 에러 발생 확인
echo 'import { db } from "@/db";' > /tmp/test-import.ts
npx eslint /tmp/test-import.ts
# Expected: no-restricted-imports 에러

# data-access 내부에서는 정상 동작 확인
# src/data-access/users.ts 에서 @/db import — 에러 없음
```

## 2. console.log 금지

### 목적

`console.log`를 금지하되, `console.warn`과 `console.error`는 허용한다.

### 왜 필요한가

디버깅용 `console.log`가 프로덕션 코드에 남으면 불필요한 출력이 발생하고,
민감한 정보가 노출될 수 있다. `warn`과 `error`는 운영 모니터링에 필요하므로 유지한다.

### ESLint 9 Flat Config

```js
// eslint.config.js
export default [
  {
    files: ["src/**/*.ts", "src/**/*.tsx"],
    rules: {
      "no-console": [
        "error",
        {
          allow: ["warn", "error"],
        },
      ],
    },
  },
];
```

### Legacy Config (.eslintrc.json)

```json
{
  "rules": {
    "no-console": [
      "error",
      {
        "allow": ["warn", "error"]
      }
    ]
  }
}
```

### 테스트 방법

```bash
# console.log 사용 시 에러 발생 확인
echo 'console.log("debug");' > /tmp/test-console.ts
npx eslint /tmp/test-console.ts
# Expected: no-console 에러

# console.warn, console.error는 허용 확인
echo 'console.warn("warning"); console.error("error");' > /tmp/test-console-ok.ts
npx eslint /tmp/test-console-ok.ts
# Expected: 에러 없음
```

## 3. 앱 간 직접 import 금지

### 목적

모노레포에서 `apps/` 하위의 앱들이 서로를 직접 import하지 못하도록 차단한다.
공유 코드는 반드시 `packages/`로 추출해야 한다.

### 왜 필요한가

앱 간 직접 import는 빌드 의존성을 복잡하게 만들고, 순환 참조를 유발한다.
각 앱은 독립적으로 빌드/배포할 수 있어야 하며, 공유 로직은 별도 패키지로 분리해야 한다.

### ESLint 9 Flat Config

```js
// eslint.config.js (apps/web 기준)
export default [
  {
    files: ["apps/web/src/**/*.ts", "apps/web/src/**/*.tsx"],
    rules: {
      "no-restricted-imports": [
        "error",
        {
          patterns: [
            {
              group: ["../../apps/api/*", "../../apps/docs/*"],
              message:
                "다른 앱을 직접 import할 수 없습니다. 공유 코드는 packages/로 추출하세요.",
            },
          ],
        },
      ],
    },
  },
  {
    files: ["apps/api/src/**/*.ts"],
    rules: {
      "no-restricted-imports": [
        "error",
        {
          patterns: [
            {
              group: ["../../apps/web/*", "../../apps/docs/*"],
              message:
                "다른 앱을 직접 import할 수 없습니다. 공유 코드는 packages/로 추출하세요.",
            },
          ],
        },
      ],
    },
  },
];
```

### Legacy Config (.eslintrc.json, apps/web 기준)

```json
{
  "overrides": [
    {
      "files": ["src/**/*.ts", "src/**/*.tsx"],
      "rules": {
        "no-restricted-imports": [
          "error",
          {
            "patterns": [
              {
                "group": ["../../apps/api/*", "../../apps/docs/*"],
                "message": "다른 앱을 직접 import할 수 없습니다. 공유 코드는 packages/로 추출하세요."
              }
            ]
          }
        ]
      }
    }
  ]
}
```

### 테스트 방법

```bash
# apps/web에서 apps/api를 import 시 에러 발생 확인
echo 'import { handler } from "../../apps/api/src/handler";' > /tmp/test-cross.ts
npx eslint /tmp/test-cross.ts
# Expected: no-restricted-imports 에러

# packages/ import는 정상 동작 확인
echo 'import { Button } from "@repo/ui/button";' > /tmp/test-pkg.ts
npx eslint /tmp/test-pkg.ts
# Expected: 에러 없음
```

---

## 참고

- ESLint 9 flat config는 `eslint.config.js`를 사용하며, `overrides` 대신 배열의 별도 객체로 분리한다.
- Legacy config는 `.eslintrc.json` 또는 `.eslintrc.js`를 사용한다.
- `no-restricted-imports`는 ESLint 내장 규칙이므로 별도 플러그인 설치가 필요 없다.
- 모노레포에서는 루트 ESLint 설정과 앱별 설정을 조합하여 사용한다.
